# MG COURS — guide de contribution

Application web personnelle de **Marie Gautron** (enseignante, plusieurs écoles) :
centraliser ressources / modules / cours / étudiants / évaluations, générer trames
pédagogiques + PDF étudiants + **factures électroniques** conformes YNOV, suivre le
workflow « iceberg » jusqu'au paiement.

**Deadline 1er cours : 12 octobre 2026.** Plan détaillé : voir `docs/ROADMAP.md`.

## Méthode de travail — BMAD allégé

Cadrage court **avant** de coder, chaque doc validé par la PO (Marie) :

| Rôle           | Livrable                                                                               |
| -------------- | -------------------------------------------------------------------------------------- |
| **Product**    | `docs/prd.md` — périmètre MVP, epics, user stories, critères d'acceptation             |
| **Architecte** | `docs/architecture.md` — stack, modèle de données (anglais), RLS, sécurité facturation |
| **UX**         | `docs/ux-ui-spec.md` — parcours, wireframes, design system, RGAA par écran             |
| **Dev**        | implémentation story par story, tests inclus, 1 PR par story                           |

## Stack

Next.js 16 (App Router, Turbopack par défaut) · React 19 · TypeScript strict ·
Tailwind v4 + shadcn/ui (base radix) · Supabase (Postgres / Auth / Storage) via `@supabase/ssr` ·
RSC + Server Actions (pas de state manager) · `@react-pdf/renderer` · Resend · Vitest ·
Playwright + `@axe-core/playwright`.

Next.js 16 : `cookies()` / `headers()` / `params` / `searchParams` sont **async** ;
`middleware` → `proxy.ts` (runtime nodejs) ; `next lint` supprimé (ESLint direct).

## Commandes

```bash
pnpm dev            # serveur de dev (Turbopack, .next/dev)
pnpm build          # build de prod
pnpm lint           # ESLint
pnpm typecheck      # next typegen + tsc --noEmit
pnpm test           # Vitest (logique métier)
pnpm test:e2e       # Playwright + axe
pnpm db:start       # Supabase local (Docker)
pnpm db:reset       # rejoue migrations + seed
pnpm db:types       # régénère src/types/database.ts
```

Node : voir `.nvmrc` (22). CI : `.github/workflows/ci.yml`.

## Règles non négociables

- **Aucune mention d'outil d'IA** (« Claude », « generated by », co-auteur…) : ni dans le
  code, ni dans les commits, ni dans les PR, ni dans l'UI, ni — surtout — dans les factures.
  `CLAUDE.md` est régénéré par `next dev` et gitignoré.
- **Modèle de données en anglais** (`snake_case`). UI et copie **en français**.
- **RGAA 4.1 / WCAG 2.1 AA** : HTML sémantique, clavier, focus géré, libellés reliés,
  `prefers-reduced-motion`. `pnpm test:e2e` doit passer axe avec 0 violation.
- **Logique métier YNOV** = fonctions pures testées dans `src/lib/ynov/` (notation, iceberg,
  invoice). Jamais dans les composants.
- Toute écriture DB via **Server Action** ou **Route Handler**, jamais depuis le client.
  Chaque table : `owner_id` + RLS `owner_id = auth.uid()`.
- **Chaque PR** met à jour `docs/BACKLOG.md` (statut US) et `docs/ROADMAP.md` si besoin.
